3. Spacing

Base unit is 4px. Section and component spacing is built from multiples of it rather than arbitrary values.

TokenValueTypical use
xs8pxIcon-to-label gaps, tight inline spacing
sm16pxCard internal padding (compact), form field gaps
md24pxCard padding, grid gaps
lg36–48pxSpace between a heading and the content below it
xl52–64pxVertical padding between full sections

Page content is constrained to a max-width: 1200px wrapper (.wrap) with 24px horizontal padding at all sizes, so it never touches the viewport edge.

Contact layout960pxContact page splits into sidebar + form columns (0.9fr / 1.4fr).

Approach: base styles target mobile; each rule is added, not overridden, at wider breakpoints via min-width media queries — a mobile-first cascade rather than a desktop-first one that gets stripped down.

9. From design to HTML/CSS — translation notes

Every colour and most spacing values live as CSS custom properties in :root, mirroring the tokens in the Brand Guidelines document — a developer implementing this from Figma would define the same variable set before writing a single component. Layout is CSS Grid for card groups and Flexbox for one-dimensional rows (nav, button groups, footer columns). No CSS framework is used — utility-class bloat was traded for a small, purpose-built stylesheet that stays legible at this project's scale. Markup uses semantic landmarks throughout (<header>, <nav>, <main> implied by section structure, <footer>), and interactive JS (nav toggle, tab switching, form validation) is isolated in script.js, unminified and commented, rather than inlined per page.

If this were rebuilt in React: six components fall out of the existing markup almost directly — <Nav /> (owns mobile-menu open state), <Hero />, <FeatureCard /> (mapped from a data array rather than repeated markup), <IndustryTabs /> (owns active-tab state, currently vanilla JS toggling display), <DemoForm /> (owns field values and validation state, currently manual DOM queries in script.js), and <Footer />. The CSS custom property system would carry over unchanged as a design-token layer regardless of framework.
